# XJJ Housekeeper（Version 1.0.0 倩影の居）

[English](README.en_US.md) | [日本語](README.ja_JP.md) | [ไทย](README.th_TH.md) | 繁體中文 | [简体中文](README.md)

面向「本地番號影片庫」的桌面管理工具：把散落在多個硬碟、多層目錄、命名不一致的影片檔整理成可搜尋的本地索引，協助你避免重複下載，並能快速定位到檔案實際位置（即使部分影片在未掛載的行動硬碟上）。

## 解決以下問題

- 下載多、硬碟多、目錄深，想找某個番號只能靠記憶翻目錄
- 檔名不規範（大小寫/前綴/後綴/網站浮水印），同一作品容易被重複下載
- 行動硬碟常常拔插，影片暫時不可存取，但仍需要知道「有沒有」與「在哪個硬碟」
- 需要替影片加標籤、做喜好標記，並在同一介面中搜尋與播放

## 為什麼選擇「本地索引」

- 完全離線：所有中繼資料與偏好資訊都保存在你的電腦上，不需連網、不依賴線上服務
- 盤位友善：即使硬碟未掛載，也能知道「我有這部作品」並查看最後一次的路徑位置
- 避免重複下載：同一作品即使檔名變動，也更容易被識別為「已存在」
- 快速檢索：支援以番號、女藝人、標籤等多欄位模糊搜尋

## 適用人群

- 擁有大量本地番號影片檔，且影片分布在多顆硬碟/多層目錄
- 希望用「本地資料庫索引」管理，而不是依賴線上服務
- 能自行維護影視資訊資料來源的使用者（支援匯入，不提供爬取功能）

## 主要功能

### 1) 檢索與瀏覽（Query）

- 模糊搜尋：支援以 番號 / 女藝人姓名 / 標籤 進行檢索
- 結果表格：分頁、排序、可設定顯示欄位
- 雙擊操作：
  - 雙擊路徑：在檔案管理器中定位檔案
  - 雙擊其他欄位：用系統預設播放器或指定播放器播放
- 喜好標記：like / dislike / deleted

### 2) 本地影片維護（Maintain）

- 掃描並匯入：支援對「單一目錄」或「父目錄（含子目錄）」批次匯入
- 複雜目錄清理：重命名/規範化為 `ABC-123.mp4` 形式（可調整多條替換規則）
- 智慧合併機制：同一個目錄可以重複掃描多次
  - 新增檔案會補進索引
  - 已收錄檔案若移動了位置，再次掃描會自動識別並更新路徑（避免「搬家」造成重複入庫）
  - 連接硬碟後重新掃描即可刷新該硬碟的最新狀態

### 3) 問題影片發現（但不直接刪除檔案）

- 破損/異常影片：一鍵列出可能無法播放的影片清單
- 重複影片：同一番號在庫中存在多筆影片記錄時可一鍵列出
- 重要說明：本應用的「刪除」僅刪除/標記資料庫記錄，不會直接刪除磁碟上的影片檔；請自行在檔案管理器中刪除

### 4) 影視資訊（女藝人歸屬、發布日期、標題）

- 目標：為某個番號補充「屬於哪位女藝人的作品」「發布日期（release_date）」「標題」等資訊，提升搜尋與統計效果
- 合規策略：為避免法律風險，本專案不提供影視資訊爬取功能；建議自行整理可信來源後匯入
- 支援匯入/匯出格式：UTF-8（可帶 BOM）的文字檔，使用 `|` 分隔，表頭固定為：

```
actress_name|video_code|release_date|title
```

範例：

```
actress_name|video_code|release_date|title
示例藝人|ABC-123|2024-01-02|示例標題
示例藝人|DEF-456||（可留空）
```

### 5) 設定與備份

- 設定：
  - 應用標題
  - UI 語言（可在應用內切換）
  - 查詢分頁大小、可見欄位
  - 標籤管理（便於檢索）
  - 重命名規則管理（用於「目錄清理/重命名」）
- 資料備份：
  - 匯出單一 JSON 備份檔（包含資料庫、設定與重命名規則）
  - 從備份檔匯入恢復
  - 初始化（清空並重建資料與設定）

## 支援的影片格式與過濾規則

- 目前支援的影片副檔名：`.mp4 .mkv .mov`
- 匯入時會自動略過極小檔案（小於 10KB，通常是無效碎片/中繼資料檔）
- 檔名規範化工具僅處理 `.mp4/.mkv/.mov`，且預設略過小於 100MB 的檔案（可調整）

## 快速開始（桌面端）

### 方式 A：從原始碼執行（適合自訂）

環境需求：

- Python 3.10+
- Poetry
- 建議安裝 FFmpeg（`ffprobe`，用於提取時長/解析度/編碼等中繼資料）

安裝依賴（專案根目錄）：

```bash
poetry install
```

啟動：

- macOS：雙擊 `startup/XJJ-Desktop.command`
- Windows：雙擊 `startup/XJJ-Desktop.bat`
- 或直接執行：

```bash
python -m ui.tkinter.app
```

首次使用建議流程：

1. 先進入「設定/備份」點擊「初始化」（建立資料庫與設定檔）
2. 進入「維護」選擇影片根目錄並執行「掃描/匯入」
3. 回到「查詢」用番號/女藝人/標籤搜尋，雙擊播放或定位檔案

預設資料位置：

- 從原始碼執行：儲存在專案根目錄下的 `output/`
  - 資料庫：`output/video_info_collector/database/video_database.db`
  - UI 設定：`output/video_info_collector/settings.json`
  - 重命名規則：`output/video_info_collector/conf/rename_rules.yaml`
- 打包執行：會落到你的使用者資料目錄（升級/卸載較不易丟資料）
  - macOS：`~/Library/Application Support/倩影の居/output/...`
  - Windows：`%APPDATA%\\倩影の居\\output\\...`

## 使用指南（按情境）

以下以「你想解決什麼事」為主，而不是把功能清單再列一次。

### 0) 開始前：建議先準備兩類目錄

- 影片長期存放目錄（你的「正式庫」）：可多硬碟、多目錄；分類方式照你的習慣（年份/類型/女藝人/系列等）。
- 臨時處理目錄（你的「收件匣/中轉站」）：專門放新下載、亂命名的檔案；清洗並確認無誤後再搬進正式庫。

好處是：重命名/清洗更安全（不會影響正式庫結構），而且資料庫裡記錄的路徑也更穩定。

### 1) Query：我想快速找到某個番號/標籤/女藝人

目標：不靠記憶翻目錄，直接定位到檔案實際路徑。

- 在 Query 頁輸入關鍵字：
  - 番號：例如 `ABC-123`（推薦）
  - 標籤：例如 `動作`、`2024`、`辦公室`
  - 女藝人姓名：匯入影視資訊後更容易命中
- 有結果後：
  - 雙擊「路徑」欄：在檔案管理器中定位檔案
  - 雙擊其他欄位：用系統預設播放器或指定播放器播放
- 若影片在外接硬碟、目前未掛載：
  - 仍可查到「最後一次的路徑位置」
  - 但播放/定位會因檔案不可存取而失敗；掛載後再試即可
- 喜好標記建議用法：
  - `like / dislike`：偏好標記，便於篩選
  - `deleted`：只影響資料庫與統計，不會刪除磁碟上的影片檔

### 2) Maintain：把影片匯入索引，並能安全重複掃描

目標：把散落在多硬碟的影片變成可搜尋的本地索引；後續搬移檔案也能更新路徑。

#### 情境 A：你已按類目整理成多級目錄，且檔名基本符合番號格式

例如：

- `/Volumes/Disk-1/folder/動作/ABC-123.mp4`
- `/Volumes/Disk-1/folder/劇情/DEF-456.mp4`
- `/Volumes/Disk-1/folder/劇情/2024/XYZ-999.mp4`

建議做法：

1. 進入 Maintain，選擇你要匯入的「頂層目錄」（例如 `/Volumes/Disk-1/folder`），執行掃描/匯入。
2. 掃描完成後會依目錄結構自動打標籤：
   - 以「首層子目錄名」作為標籤（如 `動作`、`劇情`）
   - 若你直接掃描某個葉子目錄（該目錄下直接放影片），則使用該目錄名作為標籤
3. 注意：這些自動標籤會寫入影片記錄（可用於查詢），但不會自動加入你在「設定」中維護的「標籤清單」。

#### 情境 B：新下載檔名很亂，想先清洗再入庫（強烈建議）

典型檔名：

- `example.com_abc-123_1080p.mp4`
- `【浮水印】ABC-123(uncensored).mp4`

建議流程（更安全，且路徑更穩定）：

1. 先把新下載影片放到「臨時處理目錄」。
2. 在臨時處理目錄執行檔名規範化/重命名清理，將檔名統一成 `ABC-123.mp4`，並確認沒有誤判/誤改。
   - CLI：`python -m tools.filename_formatter <臨時目錄>`
3. 確認無誤後，再把清洗好的檔案移動到你的「正式庫目錄」（按你的類目歸檔）。
4. 最後在 Maintain 掃描正式庫目錄完成匯入。

#### 重複掃描與搬家

- 同一個目錄可重複掃描：新增會補進索引；移動過位置的檔案會在再掃描時更新路徑。
- `missing` 僅相對本次掃描範圍判斷：掃描某一顆硬碟/根目錄不會把無關目錄的資料誤標 missing。

### 3) 問題影片處理：找出異常/重複，但不直接刪除檔案

目標：讓你先「看到問題清單」再做決策，避免誤刪。

- 破損/異常影片：
  - 常見情況是無法提取時長/解析度等中繼資料（可能未安裝 `ffprobe`，或檔案本身損壞）
  - 建議先安裝 FFmpeg（含 `ffprobe`），再對該目錄重新掃描
- 重複影片：
  - 同一 `video_code` 在庫中出現多筆記錄
  - 建議先按檔案大小/解析度/碼率等比對，決定保留哪一份
  - 你可刪除資料庫記錄或打 `deleted` 偏好標記；磁碟檔案的刪除請在檔案管理器中自行完成

### 4) 影視資訊如何匯入：補齊女藝人/發布日期/標題

目標：在離線索引的基礎上，補充作品資訊以利檢索與統計。

建議做法（桌面端）：

1. 在 Maintain 的影視資訊區塊點擊「匯入」。
2. 匯入檔為 UTF-8（可帶 BOM）的文字檔，表頭固定為：

```
actress_name|video_code|release_date|title
```

3. 匯入後，在 Query 以女藝人姓名搜尋也可命中（前提是 video_code 能匹配）。

### 5) 資料庫檔案如何處理：備份/搬機與 readonly 注意

目標：索引可跨硬碟，同時資料安全可遷移。

- 建議：資料庫放在本機可寫的目錄；資料庫記錄的影片路徑可以指向外接硬碟上的檔案。
- 若資料庫放在只讀卷/只讀掛載的外接硬碟，匯入/更新會失敗並出現 `attempt to write a readonly database`。
  - 把資料庫移回本機可寫位置後再繼續維護。
- 搬機/備份：
  - 使用「設定/備份」匯出單一 JSON 備份檔（包含資料庫、設定與重命名規則），在另一台機器匯入即可恢復。
  - 若只複製資料庫檔，別忘了同時處理 UI 設定與重命名規則（否則體驗會不一致）。

### 方式 B：打包並從 dist 執行（離線分發）

本專案使用 PyInstaller：

- macOS：`startup/Build-XJJ-Desktop-App.command`
- Windows：`startup/Build-XJJ-Desktop-App.bat`
- 若需一併打包 ffmpeg/ffprobe：
  - macOS：`startup/Build-XJJ-Desktop-App-With-FFmpeg.command`
  - Windows：`startup/Build-XJJ-Desktop-App-With-FFmpeg.bat`

產物位於 `dist/`。
