# XJJ Housekeeper（Version 1.0.0 倩影の居）

[English](README.en_US.md) | [日本語](README.ja_JP.md) | ไทย | [繁體中文](README.zh_TW.md) | [简体中文](README.md)

แอปเดสก์ท็อปสำหรับจัดการ “คลังวิดีโอรหัส (番号) ในเครื่อง” โดยสร้างดัชนีแบบออฟไลน์จากไฟล์ที่กระจายอยู่ตามหลายไดรฟ์และหลายโฟลเดอร์ ช่วยลดการดาวน์โหลดซ้ำ และค้นหา/ระบุพาธไฟล์จริงได้อย่างรวดเร็ว (แม้บางไฟล์จะอยู่ในฮาร์ดดิสก์ภายนอกที่ยังไม่ได้เมานต์)

## ปัญหาที่ช่วยแก้

- ไฟล์เยอะ ไดรฟ์เยอะ โฟลเดอร์ลึก หาเลขรหัสยาก
- ชื่อไฟล์ไม่เป็นมาตรฐาน (คำนำหน้า/คำต่อท้าย/ลายน้ำ) ทำให้ดาวน์โหลดซ้ำง่าย
- ฮาร์ดดิสก์ภายนอกถอดเสียบบ่อย แต่ยังต้องรู้ว่า “มีหรือไม่มี” และ “อยู่ไดรฟ์ไหน”
- ต้องการติดแท็ก บันทึกความชอบ ค้นหา และเล่นวิดีโอได้ในที่เดียว

## ทำไมต้อง “ดัชนีในเครื่อง”

- ออฟไลน์ทั้งหมด: เมทาดาทาและความชอบเก็บไว้ในคอมพิวเตอร์ของคุณ
- เหมาะกับหลายไดรฟ์: แม้ไดรฟ์ยังไม่เมานต์ ก็ยังเห็นตำแหน่งล่าสุด (พาธ)
- กันดาวน์โหลดซ้ำ: ชื่อไฟล์เปลี่ยนก็ยังระบุได้ว่า “มีอยู่แล้ว”
- ค้นหาเร็ว: ค้นหาแบบคลุมเครือด้วยรหัส นักแสดงหญิง หรือแท็ก

## เหมาะกับใคร

- ผู้ที่มีคลังวิดีโอในเครื่องจำนวนมาก กระจายหลายไดรฟ์/หลายโฟลเดอร์
- ผู้ที่อยากจัดการด้วยฐานข้อมูลในเครื่อง ไม่พึ่งบริการออนไลน์
- ผู้ที่สามารถเตรียมข้อมูลข่าวสาร/รายละเอียดผลงานเองได้ (รองรับนำเข้า ไม่ให้ฟังก์ชันสแครปโดยค่าเริ่มต้น)

## ฟีเจอร์หลัก

### 1) ค้นหา & เรียกดู (Query)

- ค้นหาแบบคลุมเครือ: รหัสวิดีโอ / ชื่อนักแสดงหญิง / แท็ก
- ตารางผลลัพธ์: แบ่งหน้า เรียงลำดับ ปรับคอลัมน์ที่แสดงได้
- ดับเบิลคลิก:
  - คอลัมน์พาธ: เปิดโฟลเดอร์เพื่อดูไฟล์
  - คอลัมน์อื่น: เล่นด้วยตัวเล่นเริ่มต้นหรือที่เลือกไว้
- ความชอบ: like / dislike / deleted

### 2) ดูแลคลัง (Maintain)

- สแกนและนำเข้า: สแกนโฟลเดอร์เดียว หรือโฟลเดอร์แม่ (รวมโฟลเดอร์ย่อย)
- ทำความสะอาดโฟลเดอร์: ปรับชื่อเป็นรูปแบบ `ABC-123.mp4` (ปรับกฎได้)
- รวมอัจฉริยะ: สแกนโฟลเดอร์เดิมซ้ำได้
  - ไฟล์ใหม่จะถูกเพิ่มเข้าดัชนี
  - ไฟล์ที่ย้ายที่แล้วจะถูกตรวจพบและอัปเดตพาธ (ไม่เพิ่มซ้ำ)
  - เมานต์ไดรฟ์แล้วสแกนอีกครั้งเพื่อรีเฟรชสถานะล่าสุด

### 3) ค้นหาวิดีโอมีปัญหา (ไม่ลบไฟล์จริง)

- วิดีโอเสีย/ผิดปกติ: แสดงรายการไฟล์ที่อาจเล่นไม่ได้
- ไฟล์ซ้ำ: แสดงรายการที่มีหลายเรคคอร์ดภายใต้รหัสเดียวกัน
- สำคัญ: “ลบ” ในแอปจะลบ/ทำเครื่องหมายเฉพาะข้อมูลในฐานข้อมูล ไม่ได้ลบไฟล์วิดีโอจริง ให้ลบผ่านตัวจัดการไฟล์ของระบบเอง

### 4) ข้อมูลผลงาน (นักแสดงหญิง / วันเผยแพร่ / ชื่อเรื่อง)

- เป้าหมาย: เติมข้อมูลให้รหัสวิดีโอเพื่อช่วยค้นหาและสถิติ
- เพื่อหลีกเลี่ยงความเสี่ยงด้านกฎหมาย แอปไม่ให้ฟังก์ชันสแครปข้อมูลข่าวสารโดยค่าเริ่มต้น กรุณาเตรียมไฟล์ข้อมูลแล้วนำเข้า
- รูปแบบนำเข้า/ส่งออก: ไฟล์ข้อความ UTF-8 (รองรับ BOM) คั่นด้วย `|` และหัวตารางคงที่:

```
actress_name|video_code|release_date|title
```

ตัวอย่าง:

```
actress_name|video_code|release_date|title
Sample Actress|ABC-123|2024-01-02|Sample Title
Sample Actress|DEF-456||optional
```

### 5) ตั้งค่า & สำรองข้อมูล

- ตั้งค่า:
  - ชื่อแอป
  - ภาษา UI (สลับได้ในแอป)
  - จำนวนรายการต่อหน้า และคอลัมน์ที่แสดง
  - จัดการแท็ก
  - จัดการกฎเปลี่ยนชื่อไฟล์
- สำรองข้อมูล:
  - ส่งออกไฟล์สำรอง JSON ไฟล์เดียว (ฐานข้อมูล + ตั้งค่า + กฎ)
  - นำเข้าเพื่อกู้คืน
  - เริ่มต้นใหม่ (รีเซ็ตข้อมูล/ตั้งค่า)

## รูปแบบที่รองรับ & เงื่อนไขกรอง

- นามสกุลที่รองรับ: `.mp4 .mkv .mov`
- การนำเข้าจะข้ามไฟล์ขนาดเล็กมาก (น้อยกว่า 10KB)
- การปรับชื่อไฟล์จะทำกับ `.mp4/.mkv/.mov` และข้ามไฟล์เล็กกว่า 100MB โดยค่าเริ่มต้น (ปรับได้)

## เริ่มต้นใช้งาน (เดสก์ท็อป)

### วิธี A: รันจากซอร์ส (แนะนำสำหรับปรับแต่ง)

สิ่งที่ต้องมี:

- Python 3.10+
- Poetry
- แนะนำ: FFmpeg (`ffprobe`) สำหรับดึงระยะเวลา/ความละเอียด/โค้ดेक

ติดตั้ง dependencies (ที่โฟลเดอร์รากโปรเจกต์):

```bash
poetry install
```

เปิดแอป:

- macOS: ดับเบิลคลิก `startup/XJJ-Desktop.command`
- Windows: ดับเบิลคลิก `startup/XJJ-Desktop.bat`
- หรือรัน:

```bash
python -m ui.tkinter.app
```

ขั้นตอนครั้งแรก (แนะนำ):

1. ไปที่ Settings/Backup แล้วกด “Initialize”
2. ไปที่ Maintain เลือกโฟลเดอร์วิดีโอ แล้วสแกน/นำเข้า
3. กลับไป Query ค้นหาด้วยรหัส/นักแสดงหญิง/แท็ก แล้วดับเบิลคลิกเพื่อเล่นหรือเปิดโฟลเดอร์

ตำแหน่งข้อมูลเริ่มต้น:

- รันจากซอร์ส: อยู่ใต้ `output/` (อ้างอิงจากโฟลเดอร์รากของโปรเจกต์)
  - ฐานข้อมูล: `output/video_info_collector/database/video_database.db`
  - ตั้งค่า UI: `output/video_info_collector/settings.json`
  - กฎเปลี่ยนชื่อ: `output/video_info_collector/conf/rename_rules.yaml`
- แอปที่แพ็กแล้ว: อยู่ในโฟลเดอร์ข้อมูลผู้ใช้ (อัปเกรด/ถอนการติดตั้งแล้วยังเก็บข้อมูลได้ง่าย)
  - macOS: `~/Library/Application Support/倩影の居/output/...`
  - Windows: `%APPDATA%\\倩影の居\\output\\...`

## คู่มือการใช้งาน (ตามสถานการณ์จริง)

ส่วนนี้เน้น “ทำอย่างไรให้ได้ผลลัพธ์” ตามสถานการณ์ใช้งานจริง ไม่ได้แค่ลิสต์ฟีเจอร์

### 0) ก่อนเริ่ม: แนะนำให้เตรียมโฟลเดอร์ 2 แบบ

- โฟลเดอร์เก็บระยะยาว (“คลังหลัก”): จะหลายไดรฟ์/หลายโฟลเดอร์ก็ได้ จัดหมวดหมู่ตามสไตล์คุณ
- โฟลเดอร์ชั่วคราว (“กล่องรับเข้า/ที่ทำงาน”): ใส่ไฟล์ดาวน์โหลดใหม่ที่ชื่อรก ๆ ไว้ที่นี่ก่อน ทำความสะอาด/ตรวจสอบ แล้วค่อยย้ายเข้าคลังหลัก

แนวทางนี้ปลอดภัยกว่าเวลาปรับชื่อไฟล์ (ไม่กระทบโครงสร้างคลังหลัก) และพาธในฐานข้อมูลจะนิ่งกว่า

### 1) Query: “อยากหาเลขรหัส/แท็ก/นักแสดงหญิงให้เจอเร็ว ๆ”

เป้าหมาย: ไม่ต้องไล่เปิดโฟลเดอร์ด้วยมือ ไปที่พาธไฟล์จริงได้ทันที

- ไปหน้า Query แล้วพิมพ์คีย์เวิร์ด:
  - รหัสวิดีโอ (แนะนำ): `ABC-123`
  - แท็ก: เช่น `Action`, `2024`, `Office`
  - ชื่อนักแสดงหญิง: จะเวิร์กขึ้นเมื่อคุณนำเข้าข้อมูลผลงานแล้ว
- เมื่อเห็นผลลัพธ์:
  - ดับเบิลคลิกคอลัมน์พาธ: เปิดไฟล์ในตัวจัดการไฟล์
  - ดับเบิลคลิกคอลัมน์อื่น: เล่นด้วยตัวเล่นเริ่มต้น/ที่เลือกไว้
- ถ้าไฟล์อยู่ในไดรฟ์ภายนอกที่ยังไม่เมานต์:
  - ยังค้นหา “พาธล่าสุด” ได้
  - แต่เปิด/เล่นจะทำไม่ได้จนกว่าจะเมานต์ไดรฟ์
- การใช้ preference ที่แนะนำ:
  - `like / dislike`: ไว้กรองตามความชอบ
  - `deleted`: ถือว่า “ลบแล้ว” ในฐานข้อมูล/สถิติ (ไม่ลบไฟล์จริง)

### 2) Maintain: นำเข้าคลัง และสแกนซ้ำได้แบบไม่เละ

เป้าหมาย: ทำดัชนีออฟไลน์ข้ามหลายไดรฟ์ และอัปเดตพาธได้เมื่อย้ายไฟล์

#### สถานการณ์ A: คุณจัดโฟลเดอร์เป็นหมวดหมู่หลายชั้นอยู่แล้ว และชื่อไฟล์ค่อนข้างเป็นรูปแบบรหัส

ตัวอย่าง:

- `/Volumes/Disk-1/folder/Action/ABC-123.mp4`
- `/Volumes/Disk-1/folder/Drama/DEF-456.mp4`
- `/Volumes/Disk-1/folder/Drama/2024/XYZ-999.mp4`

วิธีที่แนะนำ:

1. ในหน้า Maintain เลือก “โฟลเดอร์ระดับบนสุด” ที่ต้องการนำเข้า (เช่น `/Volumes/Disk-1/folder/`) แล้วสแกน/นำเข้า
2. หลังสแกนเสร็จ ระบบจะติดแท็กอัตโนมัติตามโครงสร้างโฟลเดอร์:
   - ใช้ชื่อโฟลเดอร์ย่อยชั้นแรกเป็นแท็ก (เช่น `Action`, `Drama`)
   - ถ้าคุณสแกนโฟลเดอร์ปลายทาง (มีไฟล์วิดีโออยู่ตรงนั้นเลย) จะใช้ชื่อโฟลเดอร์นั้นเป็นแท็ก
3. หมายเหตุ: แท็กอัตโนมัติจะถูกบันทึกกับรายการวิดีโอ (ค้นหาได้) แต่จะไม่ถูกเพิ่มเข้า “รายการแท็ก” ที่คุณจัดการในหน้า Settings โดยอัตโนมัติ

#### สถานการณ์ B: ชื่อไฟล์ดาวน์โหลดใหม่รกมาก — แนะนำให้ทำความสะอาดก่อนแล้วค่อยนำเข้า

ตัวอย่าง:

- `example.com_abc-123_1080p.mp4`
- `[watermark]ABC-123(uncensored).mp4`

เวิร์กโฟลว์:

1. ย้ายไฟล์ใหม่ไปไว้ในโฟลเดอร์ชั่วคราวก่อน
2. รันเครื่องมือปรับชื่อไฟล์ในโฟลเดอร์ชั่วคราว แล้วตรวจสอบผลลัพธ์ (กันการเปลี่ยนชื่อผิด):
   - CLI: `python -m tools.filename_formatter <staging-folder>`
3. ตรวจสอบแล้วค่อยย้ายไฟล์ที่ “สะอาด” ไปไว้ในคลังหลักตามหมวดหมู่ที่คุณต้องการ
4. สแกน/นำเข้าคลังหลักในหน้า Maintain

#### สแกนซ้ำ & ย้ายไฟล์

- สแกนโฟลเดอร์เดิมซ้ำได้: ไฟล์ใหม่จะถูกเพิ่ม และไฟล์ที่ย้ายที่แล้วจะถูกตรวจพบและอัปเดตพาธ
- สถานะ “missing” จะอิงเฉพาะขอบเขตโฟลเดอร์ที่คุณสแกนครั้งนั้น จึงไม่ไปทำให้โฟลเดอร์อื่น ๆ ถูกมาร์กผิด

### 3) วิดีโอมีปัญหา: ค้นหาไฟล์เสีย/ไฟล์ซ้ำ โดยไม่ลบไฟล์จริง

เป้าหมาย: ให้คุณเห็นรายการปัญหาแล้วตัดสินใจเอง ลดความเสี่ยงลบผิด

- วิดีโอเสีย/ผิดปกติ:
  - มักเกิดจากดึงเมทาดาทาไม่ได้ (เช่น duration) เพราะไม่มี `ffprobe` หรือไฟล์เสีย
  - แนะนำให้ติดตั้ง FFmpeg (มี `ffprobe`) แล้วสแกนใหม่
- ไฟล์ซ้ำ:
  - เมื่อ `video_code` เดียวกันมีหลายเรคคอร์ด
  - เปรียบเทียบขนาด/ความละเอียด/บิทเรต แล้วเลือกเก็บไฟล์ที่ต้องการ
  - ลบได้เฉพาะเรคคอร์ดในฐานข้อมูลหรือมาร์ก `deleted` ส่วนการลบไฟล์จริงให้ทำผ่านตัวจัดการไฟล์

### 4) นำเข้าข้อมูลผลงาน: เติมนักแสดง/วันที่/ชื่อเรื่อง เพื่อค้นหาและสถิติที่ดีขึ้น

เป้าหมาย: เติมข้อมูลให้ดัชนีออฟไลน์ เพื่อช่วยค้นหาและสรุปสถิติ

วิธีที่แนะนำ (UI เดสก์ท็อป):

1. ไปที่ Maintain → Movie Info แล้วกด Import
2. ไฟล์นำเข้าต้องเป็น UTF-8 (รองรับ BOM) และหัวตารางต้องเป็นแบบนี้:

```
actress_name|video_code|release_date|title
```

3. หลังนำเข้า การค้นหาชื่อนักแสดงหญิงในหน้า Query จะมีโอกาสเจอมากขึ้น (ต้องมี video_code ตรงกัน)

### 5) จัดการไฟล์ฐานข้อมูล: สำรอง/ย้ายเครื่อง และข้อควรระวัง “readonly”

เป้าหมาย: ให้ข้อมูลปลอดภัย ย้ายเครื่องง่าย และใช้งานกับหลายไดรฟ์ได้

- แนะนำ: เก็บฐานข้อมูลไว้ในที่ที่เขียนได้บนเครื่อง (local) แล้วให้พาธในฐานข้อมูลชี้ไปที่ไฟล์บนไดรฟ์ภายนอกได้ตามปกติ
- ถ้าวางฐานข้อมูลไว้ในไดรฟ์/เมานต์ที่เป็นอ่านอย่างเดียว จะเจอ error `attempt to write a readonly database`
  - ให้ย้ายฐานข้อมูลกลับไปไว้ในที่ที่เขียนได้ แล้วค่อยทำการสแกน/อัปเดตต่อ
- สำรอง/ย้ายเครื่อง:
  - ใช้ Settings/Backup ส่งออกไฟล์สำรอง JSON ไฟล์เดียว (ฐานข้อมูล + ตั้งค่า + กฎ) แล้วนำเข้าในเครื่องใหม่
  - ถ้าคุณคัดลอกเฉพาะไฟล์ฐานข้อมูล อย่าลืมย้ายไฟล์ตั้งค่า UI และกฎเปลี่ยนชื่อด้วยเพื่อให้พฤติกรรมสอดคล้องกัน
